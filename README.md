# 枝想 3.1 · 个人项目与 E2B Pi Agent

个人账号 → 多个项目 → 各项目独立的导图和 Skill 库 → 每次任务独立 E2B 沙箱。

- 仓库：https://github.com/jobop/mind
- 网站：https://mind.made-world.link
- 当前源码：https://mind.made-world.link/downloads/mind-source.zip
- 部署说明：[deploy/README.md](deploy/README.md)

## 使用

1. 注册 / 登录个人账号，创建一个或多个项目。用户名与密码登录；当前不提供自助密码找回。
2. 在「项目 Skill 库」添加多个内置方法、Markdown 或腾讯 SkillHub Skill，并勾选启用。项目背景也在这里设置。
3. 在页面配置自己的模型 Base URL、模型 ID 和 API Key，接口需要支持 OpenAI 兼容 Chat Completions、Function Calling 和 SSE。
4. 点击节点生成子问题或解决方案。Agent 检索当前项目的 Skill 目录，选择并读取 1–4 个相关方法，按需执行工具，再校验并提交分支。
5. 执行记录显示准备了哪些文件、采用哪些 Skill、工具状态和沙箱清理状态。右键节点 / 手机长按打开操作菜单。

E2B 由平台统一提供，用户不需要输入 E2B Key。项目与 Skill 的访问权限在服务器校验；提交其他项目 ID、伪造 Skill 内容或借用其他账号的模型 Cookie 均不能获得对应权限。

## 任务沙箱

1. 从服务器取得当前账号当前项目启用的 Skill 快照。
2. 对 SkillHub 来源按固定版本读取文件，逐文件 SHA-256 校验，缓存在该项目独立的目录。项目审核 / 编辑过的 SKILL.md 优先；脚本和引用文件保持固定版本。
3. 使用平台 E2B Key 创建一个全新沙箱，最长生命周期 20 分钟，不复用其他任务的 VM 或快照。
4. 通过 E2B 文件 API 上传无凭证的 Node/Pi 运行包，准备独立的 `skills/<id>/SKILL.md`、脚本与引用文件。所有文件准备好后，才启动 Pi Agent 工具循环。
5. Agent 在沙箱内运行；`read_skill` 从真实文件读取方法。`read_task_file`、`write_task_file` 和 `run_command` 可用于执行 Skill 的本地步骤。
6. 正常结束、报错、取消或超时均在 finally 中请求销毁沙箱；销毁未确认会显示待清理，平台固定生命周期兜底回收。

沙箱不挂载宿主机文件、数据库或 Docker Socket，E2B Key 和真实模型 Key 都不会传入沙箱。沙箱默认禁止直接出网；模型调用和公开网页读取经过平台受限代理。代理固定模型目的地址、限制调用预算、拒绝私网 DNS，并固定验证后的连接地址。模型凭证仅在平台发往用户配置的模型服务时使用。

命令可使用默认 E2B 模板提供的 Python3 和上传的 Node；单条命令最长 15 秒、输出最多 32KB。网络安装依赖不开放；需额外依赖时由维护者提供预装的 E2B 模板，不能把未执行成功的步骤描述为完成。Skill 文件最多 40 个 / 4MB，每个任务的 Skill 总文件最多 16MB；超限会明确拒绝，不静默省略。

Agent 预算为 20 次模型请求、60 次工具调用、5 个公开网页、15 分钟循环时间。最后 4 轮停止探索，优先校验、修订和提交。E2B 任务最多 18 分钟，VM 固定生命周期 20 分钟，不自动续租。后台作业最长 21 分钟，浏览器观察窗口 22 分钟，刷新可以重新查询同一作业。模型调用与 E2B 都可能产生费用，预算不是金额保证。

## 平台配置与启动

需要 Linux Node.js 22.19+；E2B 上传包需包含 Linux Node。线上工作流在 Linux 构建。

```sh
npm ci --ignore-scripts
npm run build
npm run sandbox:bundle
E2B_API_KEY=平台凭证 npm start
```

维护者在环境中设置 `E2B_API_KEY`；可选 `E2B_TEMPLATE_ID`，留空使用 E2B 默认 base 模板。不要将真实值写入源码或提交 `.env`。默认监听 `http://localhost:3000`。Windows/macOS 如需运行平台，应使用 Linux 环境或连接已部署网站；源码中的启动脚本可用于基本服务，但跨系统 Node 二进制不能直接上传 Linux 沙箱。

阿里云部署：在 GitHub Actions Secrets 配置 `ALIYUN_SSH_PASSWORD` 和 `E2B_API_KEY`；可选仓库 Variable `E2B_TEMPLATE_ID`。推送 main 运行 CI，手动执行工作流部署。凭证单独通过 SSH 传到服务器的 `/etc/mind/mind.env`（0600），不进入应用 / 源码压缩包，也不出现在前端设置中。

流水线在有 E2B Secret 时先做真实 E2B 冒烟测试，通过后部署；测试使用真实 VM、真实 Pi SDK 和脚本，但模型 SSE 响应受控，不消费付费模型额度。

## 数据与迁移

- SQLite：`DATA_DIR/projects.sqlite` 保存个人账号（scrypt 密码散列）、散列会话 Token 和按 owner_id 隔离的项目。项目包含多张导图、背景与多个 Skill。
- 会话使用 HttpOnly / SameSite=Strict Cookie，HTTPS 使用 Secure 和 __Host- 前缀。模型 Key 用 AES-GCM 加密在当前浏览器 Cookie 中，并绑定账号，7 天过期。
- 保存带 revision 校验，其他页面已修改时返回冲突，不覆盖新版本。未同步时页面显示重试入口，并在关闭时提示。
- 旧版 localStorage 导图不会自动归给任意登录者。登录后点击「迁移旧版浏览器导图」迁入独立项目，收集原来的 Skill，本地原件保留。
- 导图 JSON 导出包含项目 Skill 快照，不包含任何凭证。项目之间导入是用户显式操作。
- 备份服务器 `DATA_DIR`（线上 `/var/lib/mind`），包括加密密钥、数据库及 SQLite WAL；在线备份应使用 SQLite backup API 或先停服务复制，不能只复制繁忙的单个 DB 文件。

## Pi 与工具

锁定官方依赖 `@earendil-works/pi-agent-core` / `@earendil-works/pi-ai` 1.5.2、E2B SDK 2.64.0。官方 Pi：https://github.com/earendil-works/pi 。

项目任务的工具包括：计划、读取节点上下文、检索项目 Skill 目录、从文件读取 Skill、读取 / 写入任务文件、执行沙箱命令、读取公开网页、校验候选分支、提交分支。SkillHub 搜索用于用户给项目选 Skill；任务不能自行从公共库加入未授权 Skill，也不能读取其他项目。

没有读取方法、没有经过校验、只输出文字或伪造网页来源编号均不能提交节点。结构校验不代表事实核验或独立专家评审；重要结论仍需证据。失败原因经过脱敏；重试成功会标记后续已修复，旧版没存下来的具体错误不能补回。

### 3.0.1 画布生成反馈

画布内可直接生成下级节点、查看进度、取消或重试；成功后显示新增数量并自动居中，失败在画布内直接显示原因。浏览器任务等待时限调整为 7 分钟，覆盖 Skill 准备、E2B 初始化、Agent 循环及清理的完整预算。保存项目时立即锁定生成，避免快速连点发出重复任务。

## 3.1 后台任务、整树上下文与断线恢复

生成使用短请求创建后台任务，然后按任务 ID 查询增量进度。浏览器断线、关闭页面或刷新不取消任务；同一个 clientRequestId 重试不会重复调用模型。成功结果和目标节点更新在同一 SQLite 事务中落盘，完成后浏览器读取服务器上的最新导图，而不是依赖长连接收到结果后再保存。

任务记录与项目同属个人账号，查询 / 取消均校验所有权。只持久化项目输入、进度、结果和脱敏错误，不持久化模型 Key 或 E2B Key。失败记录不会再被节点创建时的旧成功记录覆盖。显式取消会中止执行并清理沙箱；正常服务更新也会中止和清理活动任务。若进程异常终止，重启会把遗留任务标记为中断，不自动重跑付费调用，E2B 固定生命周期回收孤立 VM。

每次任务从服务端项目读取选中导图的整树快照，保存为沙箱 `map-context.json`。通过稳定节点 ID 和先序序号指定展开目标。Agent 必须先读取全树概览和选中节点，再选择并读取项目 Skill。普通导图的概览包含全部节点；大树先压缩备注，仍超预算时明确标记省略节点数，并可用 `read_map_node` 按节点 ID / 序号读取完整详情。日志会显示总节点数和目标序号。其他项目、其他导图的数据不进入该快照。

SkillHub 文件准备、SKILL.md 实际读取、脚本执行和方法应用是不同阶段。没有额外的“激活”开关；执行记录证明读取 / 工具执行，内容质量仍需检查是否落实了方法，而不是只引用 Skill 名称。

## 3.1.1 模型流式代理与计划兼容

模型请求仍从平台服务器发往用户配置的模型 API，真实 Key 不进入沙箱。响应通过增量 SSE → 流式 RPC → E2B ReadableStream 传送，使用小缓冲合并网络包，不等待整条响应结束才交给 Agent。网页继续查询后台任务进度，断线恢复机制不变。

模型调用分别限制首包等待 120 秒、已开始流后空闲 90 秒、单次总耗时 5 分钟；不会因为持续流超过原先的 45 秒总时限而中断。HTTP 鉴权、余额、限流、非 SSE、流中断及转发错误有独立的脱敏原因。正常读取到流结束时的取消不计为模型失败；显式取消和任务总时限仍能停止请求并清理沙箱。

plan_work 优先使用字符串数组，同时兼容常见带 title/action/description 的步骤对象和分行文字。接受 1–20 项有意义的步骤，显示时压缩过长描述；空计划或缺少行动文字仍会拒绝。分支的内容、结构与来源校验保持独立执行。

## 3.1.2 分离模型 token 预算与传输限制

此前 2 MiB 上限是整条 SSE 的原始传输字节数，包含重复事件头、JSON 字段和思考 / 工具增量，不代表模型的上下文窗口或最终答案大小。现将累计流式传输上限调整为 64 MiB，并通过背压限制待转发队列，保持逐块转发。单个 SSE 事件仍限制 1 MiB；请求传输上限为 8 MiB，沙箱单条 IPC 上限为 24 MiB。超限提示明确指出是平台传输限制。

输出预算取消硬编码 3600 tokens，默认 8192，可在「模型设置 → 输出预算」调整为 128–65536 的整数；此值随连接加密保存，Agent 与平台代理使用同一预算。请按实际服务商支持范围设置，这些默认值并非对 GLM 官方容量的判断。

### 3.1.3

手机导图支持双指张开放大、合拢缩小，以两指中心为缩放基准；双指平移与抬起一指后的单指拖动连续衔接。保留节点点选和长按菜单，双指操作不会误触节点编辑或长按菜单。

### 3.2.0 — 节点参考资源

节点支持最多 20 个 Git 仓库、图片、视频、网页资源，资源按个人项目隔离，可在同项目节点间复用。上传图片支持 PNG/JPEG/WebP（2 MiB），视频支持 MP4/WebM（20 MiB），项目文件总量 100 MiB。文件、说明和 Git 只读 Token 保存在服务器持久 SQLite；Token 使用服务器密钥 AES-256-GCM 加密，不进入节点、浏览器存储、导出文件、模型或 E2B 沙箱。

Agent 通过 read_reference 按整树节点资源 ID 读取资料：GitHub / GitLab.com 可列目录、读文本文件并指定分支；服务器检查公网 DNS 并固定连接，拒绝携带凭证的 URL 和重定向。其他 Git 地址可作为链接保存。模型设置开启图片输入时，图片通过 Pi 的真实视觉内容传给模型；未启用时明确只读取文字说明。视频可预览播放，Agent 当前只读取说明/字幕，不自动解析视频画面和音轨。

JSON 导出仅包含资源描述和链接，不包含任何凭证或上传文件内容；跨项目导入后需重新上传文件并填写私有仓库凭证。删除项目会级联删除该项目资源、文件和加密凭证。

### 3.2.1 — 工作空间 Git 凭证

Git Token 改为在「项目设置 → 工作空间 Git 凭证」统一管理。每个个人项目独立配置 GitHub / GitLab.com 默认只读 Token，所有节点、仓库自动按平台复用。节点资源不再接收凭证；删除节点或资源不会删除工作空间凭证，更新 Token 无需逐节点修改。凭证仍在服务器加密存储，不进入模型、沙箱、导图和导出内容。

启动时事务迁移旧资源上的加密凭证：同一项目、平台只有一种 Token 时提升为工作空间默认；存在不同 Token 时按原仓库保留在工作空间历史列表，新默认配置优先使用。清除平台默认凭证会同时清理该平台历史凭证，防止撤销后自动回退。其他项目的凭证不受影响。

### 3.2.2 — 手机触摸与断线恢复

修复长按节点触发重绘后触点未释放，导致后续单指被当成双指的问题。全局捕获手指释放/取消事件，页面隐藏或新一轮单指操作会清理旧状态；节点上单指滑动也可平移画布，双指才缩放。

HTML/非 JSON 的网关错误保留 HTTP 状态并触发后台任务重连，使用原请求 ID 查询，避免重复启动模型任务。应用异常仍返回 JSON。网页读取失败现在区分站点 HTTP 状态、下载文件、无可提取正文、DNS 和读取时限，错误传给 Agent 修复，页面不展示原始响应、凭证或请求内容。

发布前会只读检查后台任务数量，等待已有生成任务结束后再重启应用；等待超时则保留当前服务并退出部署，不主动取消任务。

### 3.2.3 — 长按菜单防误触

拦截长按节点重绘后被浏览器重新指向菜单的松手点击，防止打开菜单的同一次长按直接触发生成、模型设置等操作；下一次独立点击可立即正常选择菜单项。

### 3.3.0 — 参考资料缓存与模型中断续跑

每个任务按资源 ID、规范化文件路径和目录标记缓存读取结果，重复读取复用原 S 编号，不再占用读取额度或重复堆积文件/图片。不同资源路径额度从 8 调整为 32，正文累计 64000 字符、图片累计 4 MiB；达到预算、反复读取同一资料或重复请求失败路径时进入收尾阶段，使用 Pi 的工具声明移除探索工具，只保留上下文、Skill、校验与提交。未读取到的资料必须作为待核查信息。

流空闲等待从 90 调整为 180 秒，单次模型调用总时限仍为 5 分钟。模型流超时、断开或服务端 5xx 可在同一 Pi Agent、同一沙箱和同一任务内最多恢复 2 次，保留已完成的工具结果和引用，只移除未完成且未执行工具的那条响应。20 轮模型调用和 15 分钟任务时限共同覆盖恢复次数。鉴权、余额、请求格式等错误及用户取消不自动恢复。日志显示缓存复用、资料收束和模型连接恢复。

### 3.3.1 — 区分模型静默与沙箱转发等待

向 E2B 转发队列等待消费期间暂停模型空闲计时，避免上游数据已经到达、下游转发较慢时误报「模型没有新数据」。模型请求总时限和转发超时仍然生效；真实上游静默仍按 180 秒处理。
